# 路考影片和標註怎麼對齊

CamVid 的標註每秒一張（標註幀號間隔 30），檔名是 `<段落>_f<幀號>.png`。路考播的是原始影片，所以要知道每張標註對上影片的哪一幀，才能把答案放到正確的幀上。

## 方法

`scripts/align_video.py`（判斷規則在 `src/road_test/alignment.py`，有測試）：

1. 整支影片縮到 96×72 灰階，用相關係數替每張標註原圖找候選幀。
2. 候選幀前後各 3 幀縮到 480×360，跟 CamVid 原圖比平均像素差（0～255），取最小的那幀。
3. 相鄰幀的平均像素差比對上那幀多 1.5 以上，才算「對得清楚」。對得清楚的標註，位移（影片幀號 − 標註幀號）都要一樣。
4. 車子停住時前後幾幀幾乎一樣，分不出是哪一幀。這種標註不投票；照位移取哪一幀畫面都一樣。

```powershell
uv run python scripts/align_video.py <影片> --sequence 0006R0 --csv docs/alignment/0006R0-MXF.csv
```

## 結果

每一張標註的結果都在 `docs/alignment/*.csv`。

| 影片 | 幀數 | 標註 | 位移 | 對上的平均像素差 | 相鄰幀 | 分不出的 |
|---|---|---|---|---|---|---|
| 原始影片 `0006R0.MXF`（模擬路考） | 7170 | 101 張，f00930～f03930 | **+1**（101 張都是） | 1.19～3.28，中位數 2.12 | 4.17～30.82，中位數 12.43 | 0 |
| 路考 MP4 `0006R0.mp4` | 3931 | 同上 | **0**（101 張都是） | 1.89～4.80，中位數 3.30 | 4.30～30.74，中位數 12.22 | 2：f02310、f02340（慢速），最像的仍是 0 |
| 路考 MP4 `Seq05VD.mp4`（正式路考） | 5101 | 171 張，f00000～f05100 | **0**（171 張都是） | 2.07～4.41，中位數 3.07 | 2.45～25.89，中位數 13.45 | 32：f01890～f02850 停紅燈，最像的仍是 0 |

- 0006R0 的原始影片跟 Seq05VD、0016E5 一樣：**影片幀號 = 標註幀號 + 1**（影片從 0 起算）。影片有 7170 幀，標註只到 f03930，沒有超出影片長度。
- Seq05VD 的原始影片（`0005VD.MXF`，6600 幀）之前也逐張驗證過是 +1。
- 抽查開頭、中段、結尾（`0006R0-MP4.csv`）：f00930 → 第 930 幀（差 2.96，相鄰 12.41）、f02430 → 第 2430 幀（差 4.39，相鄰 17.29）、f03930 → 第 3930 幀（差 3.13，相鄰 11.77）。

## 轉成路考 MP4

去掉影片第 0 幀、剪到最後一張標註，MP4 第 n 幀就是標註 f(n)：

```powershell
ffmpeg -i 0006R0.MXF -map 0:v:0 -vf "trim=start_frame=1:end_frame=3932,setpts=PTS-STARTPTS" `
  -c:v libx264 -crf 26 -preset medium -pix_fmt yuv420p -an -movflags +faststart 0006R0.mp4
```

960×720、29.97 fps、3931 幀、約 68 MB。前 31 秒（f00000～f00929）沒有計分幀。

## 答案框的目視檢查

```powershell
uv run python scripts/overlay_answers.py <路考.mp4> $env:ROAD_TEST_DATA\answers\0006R0.json 對照圖.png
```

綠框是必看，灰框是非必看。兩場路考都檢查過：0006R0 的第 930、3270、3300、3930 幀，Seq05VD 的第 0、1200、3600、5100 幀，框都貼著東西，沒有偏移。
